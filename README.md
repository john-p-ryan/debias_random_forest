# Debias Random Forest Regression Predictors

Python (`debiasforest`) and Julia (`DebiasForest.jl`) implementations of the random forest
bias-correction methods compared in Chen, Withana Gamage & Ryan (2022), with reproducible
simulations and a UCI Yacht regression demo.

## Methods

| Paper | Python | Julia |
|---|---|---|
| Un (uncorrected) | `default_forest()` or any fitted sklearn bagging ensemble | `fit_forest(X, y)` |
| De / Qu / Cu / Sp (univariate smoothing) | `SmoothedForestRegressor(method="linear"/"quadratic"/"cubic"/"spline")` | `fit(SmoothedForest, X, y; method=:linear/...)` |
| Bf, Bf(k) (boosted forest) | `BoostedForestRegressor(n_iterations=1, stopping="fixed"/"oob")` | `fit(BoostedForest, X, y; n_iterations=1, stopping=:fixed/:oob)` |
| Cond (conditional bias, Lu & Hardin 2021) | `ConditionalBiasForestRegressor()` | `fit(ConditionalBiasForest, X, y)` |
| Stopping rule (§2.2.2) | `select_n_iterations(X, y, max_iterations=6)` | `select_n_iterations(X, y; max_iterations=6)` |
| Full comparison | `predict_all_methods`, `simulation_study`, `repeated_splits` | same names |

- Both packages track bootstrap (in-bag) membership, expose bias-corrected OOB predictions
  (`oob_prediction_` / `oob_prediction`), and can reuse one fitted base forest for every method.
- `n_iterations` is the number of residual forests fitted after the base forest:
  0 → Un, 1 → Bf (the paper's one-step correction, the default), k+1 → Bf(k); `paper_label(k)`
  gives the paper's notation.
- The spline method is a native port of R's `stats::smooth.spline` (GCV, R's knot subset and
  spar search) in both languages, checked against fixtures generated by `dev/spline_reference.R`.
- Forest defaults follow R `randomForest` as used in the paper: 500 trees,
  `mtry = max(floor(p/3), 1)`, node size 5. Python wraps scikit-learn (≥ 1.4); Julia builds
  DecisionTree.jl trees in its own bagging loop and provides an MLJ interface.

## Quick start

Python (3.10+):

```sh
uv venv --python 3.12 && source .venv/bin/activate
uv pip install -e "python[test,demo]"
```

```python
from debiasforest import BoostedForestRegressor

model = BoostedForestRegressor(n_iterations=1).fit(X_train, y_train)
y_pred = model.predict(X_test)
```

Julia (1.10+):

```julia
using Pkg; Pkg.develop(path="julia")
using DebiasForest
model = fit(BoostedForest, X_train, y_train; n_iterations=1)
y_pred = predict(model, X_test)
```

See [`python/README.md`](python/README.md) and [`julia/README.md`](julia/README.md) for the full APIs.

## Layout

- `python/`: scikit-learn-compatible package and pytest suite (`cd python && pytest`).
- `julia/`: Julia package, MLJ models and tests (`julia --project=julia -e 'using Pkg; Pkg.test()'`).
- `demo/`: `debias_demo.ipynb` (Python) and `debias_demo.jl` (Julia), with committed tables in
  `demo/results/{python,julia}/` and figures in `demo/figures/{python,julia}/`.
- `dev/spline_reference.R`: regenerates the `smooth.spline` test fixtures (needs only base R).

## Running the demos

```sh
# Python (about 37 min on 4 cores; DEBIAS_DEMO_QUICK=1 for a ~30 s smoke run)
jupyter nbconvert --to notebook --execute --inplace demo/debias_demo.ipynb
# Julia (about 38 min with 4 threads; DEBIAS_DEMO_QUICK=1 for a smoke run)
julia -t 4 --project=demo demo/debias_demo.jl
```

The demos reproduce Fig. 1 (OOB prediction vs true function), Tables 1–2 (simulations with
K = 200 replications instead of 1000), Fig. 5 (test error vs boosting iterations) and the Yacht
row of Table 4 (100 random 2/3–1/3 splits). Yacht is downloaded on first use and cached in
`demo/data/` (UCI first, then a GitHub mirror); the Yacht sections are skipped when offline.

## Results compared with the paper

- **Function 1 (Friedman 1)** matches Table 1 closely in both languages. At σ = 1: Un 6.34 / 6.47
  (Python / Julia) vs 6.44 in the paper; Bf 3.37 / 3.40 vs 3.39; Bf(1) 2.92 / 2.93 vs 2.95.
  Univariate smoothing roughly halves the squared bias; boosting with one or two extra
  iterations removes most of the rest. At σ = 4, as in the paper, no method helps much.
- **Function 2** matches Table 2 closely. **Functions 3–5** reproduce the paper's rankings
  (boosted forest wins, Bf(1)–Bf(2) best) but not its magnitudes; Function 5 errors are about
  2.5× the paper's. These are the authors' own functions and some setup detail is probably
  unstated. We use the formulas as printed (including `3x2` in Function 2, where Friedman's
  original has `3x3`).
- **Yacht:** boosted forest is clearly best; the stopping rule selects Bf(1) in Python and Bf in
  Julia (their mean errors are within noise of each other), matching the paper's finding that one
  or two iterations suffice. Errors are above the paper's, more so in Python (Un 18.2) than
  in Julia (Un 14.3, paper 12.9). scikit-learn counts the node-size limit in distinct rows while
  R and our Julia loop count bootstrap draws, so sklearn trees are shallower. The spline
  correction is unstable on Yacht (GCV sometimes picks df ≈ 45); our port agrees with R on those
  fits, so this is a property of the method on this data.
- **Bf(k) column labels:** with the labeling above, our Bf(k) values for k ≥ 1 often line up
  with the paper's Bf(k+1) column, and the paper's Bf and Bf(1) columns are nearly identical in
  most rows. The paper's Bf(k) may therefore count total residual forests (Bf(1) ≡ Bf). The
  packages expose `n_iterations` directly, so either reading can be reproduced.
